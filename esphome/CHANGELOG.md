# Changelog

## 0.6.3

- Translates every stored left/right finger label at render time, so changing the live display language also updates the identity detail shown after a successful scan without reflashing.
- Adds source-level coverage for both languages across idle, access, denial, enrollment, deletion, offline, door, keypad and finger-position display states.

## 0.6.2

- Explicitly publishes the `Fingerprint reader firmware version` diagnostic entity during every boot in both hardware profiles, preventing Home Assistant and Access Manager from retaining an `unknown` state.

## 0.6.1

- Lets each installation map its own ESPHome secret key names through package substitutions instead of requiring fixed `wifi_ssid`, `wifi_password`, `api_encryption_key`, and `ota_password` names.
- Keeps secret values in the installation-owned wrapper and `secrets.yaml`; the reusable firmware package receives only resolved secret substitutions.
- Uses the ESPHome component-qualified header path so ESP-IDF builds include the fingerprint name store reliably.
- Moves the canonical firmware source into the Access Manager repository under `esphome/` and uses `firmware-v0.6.1` as its unambiguous release tag.

## 0.6.0

- Adds a persistent English/Spanish display-language selector controllable from Home Assistant and Access Manager.
- Translates every display state, including the two-tap door-lock confirmation.
- Keeps internal event states language-neutral so changing the display language does not affect access logic.
- Publishes the new firmware version for managed OTA updates.

## 0.5.0

- Adds ESPHome project metadata and a diagnostic firmware-version entity so Access Manager can report installed and recommended reader versions.
- Adds a display-free, reader-only profile with configurable ESP32 board ID and UART pins for Grow-compatible sensors.
- Makes both hardware profiles consumable as release-pinned remote packages generated by Access Manager 0.10.0.
- Validates the reference display and generic reader-only configurations in CI.

## 0.4.0

- Adds door-scoped Access Manager display feedback for successful opening actions, keypad credential capture, and denied keypad credentials.
- Stores the Access Manager door assignment locally, rejects mismatched or duplicate events, and restores the normal screen after four seconds.

## 0.3.1

- Replaces the initial local AXS5106L prototype with a pinned, field-tested ESPHome external component used on the same Waveshare ESP32-C6-Touch-LCD-1.47 board.
- Uses the controller's required STOP-separated register selection, 45 microsecond settling delay, and raw I2C read.
- Configures the GPIO21 interrupt input with its required pull-up while retaining the lock-only two-tap flow.
- Shows the complete local lock flow in Spanish with labels sized for the 172-pixel display.

## 0.3.0

- Adds an auditable local ESPHome driver for the Waveshare AXS5106L touch controller at I2C address `0x63`.
- Uses the ESP32-C6-Touch-LCD-1.47 touch pinout and the orientation from Waveshare's reference demo.
- Adds a six-second two-tap flow that can request only `lock`: the first tap presents a large confirmation button and the second tap inside it emits one local action.
- Cancels the pending action when the second tap is outside the button or the confirmation expires.
- Ignores local touches during fingerprint enrollment, deletion, scanning, and result screens.
- Shows `LOCK REQUESTED` after publishing and `OFFLINE` when Home Assistant is unavailable.

## 0.2.0

- Adds a one-shot Default/Open/Unlock/Lock action selector for the next successful scan.
- Appends the requested action to matched access events for capability checking by Access Manager.
- Restores the event sequence across reboots to avoid duplicate event identifiers.
- Documents how custom physical controls or touchscreens can request a lock action before authentication.

## 0.1.0

- Publishes a credential-free ESPHome reference configuration for an ESP32-C6 fingerprint access reader.
- Supports 50 fingerprint IDs and persistent local ID, person-name, and finger mappings.
- Shows access, denial, enrollment, deletion, and error states on a 172 x 320 display.
- Exposes management and access events for the Home Assistant Access Manager add-on.
- Uses ESPHome secrets for Wi-Fi, API encryption, and OTA authentication.
